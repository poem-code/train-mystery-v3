## 二、包体与性能预算

| 项 | 预算 | 实测 | 结论 |
|---|---|---|---|
| 代码包（不分包） | 总上限 **20 MB** | 约 1.3 MB | 余量充足，**不需要分包** |
| 主包（若分包） | 4 MB | — | 本工程不触发这条 |
| `js/` 源码 | — | 400 KB（45 文件 / 9,816 行） | 打包后约 304 KB |
| `assets/audio` | — | 928 KB（12 音效 123 KB + 3 首 BGM 775 KB） | BGM 已压到 11025Hz 单声道 |
| 首屏时间 | < 2s | 纯 JS + 无网络请求，实测首屏基本等于解析时间 | 达标 |
| 帧率 | 低端机 ≥30fps | 脏渲染下静态界面几乎零绘制 | 达标 |
| 单帧绘制 | < 8ms | 设置页「复制诊断信息」看 `worstRenderMs` | 需真机复核 |

> 包体还有 2.7 MB 余量。**不要为了省体积砍音效**——音效是这个游戏打击感的主要来源。
> 真要扩内容（图集、真人音效），优先吃掉这部分余量，再考虑分包。

## 三、真机自测清单

按顺序走一遍，每项都要在**真机**上做，开发者工具不算。

### 启动与存档

- [ ] 冷启动进首页，无白屏、无黑屏超过 1s
- [ ] 进主城 → 关掉进程 → 重进，以太/等级/图鉴进度都在
- [ ] 老存档（schema 3）升级后不丢数据（可拿旧包先存一份再装新包）
- [ ] 设置页「重置存档」后回到初始状态，且**不会因为残留字段崩**

### 玩法闭环

- [ ] 完整走完一局：出发 → 8 层 → Boss → 结算，三资源变化与结算数字一致
- [ ] 一局内至少遇到：1 次精英（带词缀徽标）、1 次事件、1 次商店、1 次宝箱
- [ ] 精英战斗里词缀确实生效（打「壁垒」应该看到护盾，「残响」应该复活一次）
- [ ] 逃跑、重战卡、秒杀卡、药剂四种特殊操作都能正常结算
- [ ] 阵亡结算 → 以太到账 → 回主城

### 长线系统

- [ ] 图鉴四页都能翻，进度百分比与条目数一致，跨 25% 档位时发以太
- [ ] 成就达成时弹提示，且**不会重复发**
- [ ] 观景台升到 Lv.1 后每日挑战可进；未升级时提示解锁条件
- [ ] 每日挑战通关后**主档以太与道具不变**，奖励单独到账
- [ ] 货舱升级后开局道具多了，但**不会因为放弃重开而刷道具**（只补到保底）

### 音频与前后台

- [ ] 音乐与音效可以分别关闭，关掉后不占通道
- [ ] 切后台音乐暂停，回前台恢复，**不出现两首同时播**
- [ ] 战斗结束切场景时 BGM 是渐变切换，不爆音

### 异常与诊断

- [ ] 设置页「复制诊断信息」能复制出文本，含 fps / 慢帧 / 最近日志
- [ ] 断网、切后台、连续快速点击，不出现卡死或黑屏

### 屏幕适配

- [ ] 360×640（小屏安卓）
- [ ] 390×844（主流 iOS）
- [ ] 768×1024（平板 / 折叠展开）
- [ ] 刘海屏：顶部安全区不让位（标题不被遮）
- [ ] 底部安全区：最后一行按钮不被系统手势条盖住

预览页可以快速验分辨率：`tools/preview.html?w=360&h=640`

## 四、风控点（这几条不能放松）

| 风险 | 已做的处理 | 别退回去 |
|---|---|---|
| 激励视频未配广告位却发奖 | `ad.isConfigured()` 为 false 时按钮显示不可用，**明确不发奖** | 图省事改成「先发奖再看广告」，会被判刷量 |
| 弹窗开着能点到底下按钮 | 命中区栈：后绘制者优先 | 不要为了「点得快」改成从栈底找 |
| 改档刷每日奖励 | `sanitizeDaily` 按 `dateKey` 重推导限制条件 | 不要把限制条件存进存档再直接读 |
| 改档注入不存在遗物 | `sanitizeIdMap` 只保留已知 id | 不要信任任何存档里的 id 数组 |
| 开局-放弃-再开局刷道具 | `topUpItems` 只补到保底，不叠加 | 不要改成「每次开局累加」 |
| 成就/图鉴重复发以太 | 奖励档位记录在 `progress`，发放前比对 | 不要在弹窗显示时再发一次 |
| 一天刷爆广告次数 | `adDailyLimit = 15` | 不要去掉上限 |

## 五、上线后的头三个数（灰度看这个）

只看两个数，别贪多：

1. **第 2 局开始率** —— 决定留存的唯一前置指标。低于 50% 说明首局体验有问题，去看首局阵亡层数分布。
2. **崩溃率** —— 高于 1% 立刻停投，用玩家发来的「复制诊断信息」文本定位。

第三个（有余力再看）：**每日挑战参与率** —— 这是长线系统有没有起作用的直接证据。
如果低于 10%，不是内容不够，是入口不明显或奖励不划算。

## 六、上不了线时怎么办

如果 AppID / 资质 / 版号在时间点内拿不到：

- 游戏**本身完整可玩**，可以打包成 H5（`tools/build-bundle.js` + `preview.html`）走网页演示
- 答辩/评审场景用截图 + 真机录屏（`_shots/` 已有素材）
- 代码与文档完整，换主体重新提审不需要改任何逻辑

这是「不留死路」的设计：所有平台能力都收敛在 `js/platform/`，一处降级不影响玩法。
