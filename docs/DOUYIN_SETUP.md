# 抖音侧配置：AppID 与广告位 ID

> 这份文档只讲「平台侧要做什么」，不讲代码实现。
> 平台规则会变，文中的准入条件、审核时长以**你后台实际显示为准**；本文标注了哪些是官方文档明文、哪些是实践口径。

---

## 〇、先澄清一件事

**这工程本来就是抖音小游戏，不是网页游戏。**

```
game.js              ← tt 小游戏入口（平台按这个文件启动）
game.json            ← tt 小游戏配置（竖屏、状态栏、超时）
project.config.json  ← 开发者工具配置（appid / compileType: game）
js/platform/         ← 所有 tt.* 能力收敛在这里（canvas / 音频 / 存储 / 广告 / 分享 / 震动）
```

`tools/preview.html` 不是另一个产品，是**调试通道**，用途见第四节。
交付物只有一份：这个目录打出来的 tt 小游戏包。

---

## 一、AppID 是什么

小游戏在抖音开放平台的**唯一身份编号**，创建应用后由平台生成，形如 `tt` 开头的一串字符。

| 用在哪 | 具体作用 |
|---|---|
| 抖音开发者工具 | 导入项目时必填，工具靠它认项目、连后台 |
| 真机预览 / 上传代码 | 扫码预览、提交审核都绑定这个 AppID |
| 平台能力 | 分享、排行榜、广告、云存储、数据分析全部挂在它下面 |
| 后台 | 看留存/收入/崩溃数据，都在这个应用下 |

它不是密钥。泄漏不会直接导致安全问题，但**别到处贴**——回头排查问题、确认主体归属会乱。

---

## 二、怎么拿到 AppID

### Step 1 · 注册账号

打开 <https://developer.open-douyin.com>，右上角注册（手机号或邮箱）。

### Step 2 · 主体认证

认证通过才能创建小游戏。

| 主体 | 需要 | 备注 |
|---|---|---|
| 个人 | 身份证 + 手机号实名 或 银行卡三要素（二选一） | 审核约 1 个工作日 |
| 企业 | 营业执照 + 对公打款验证 | 需先提交资质再打款 |

**选错主体改不了**（平台只支持工商更名，不支持主体变更）：

- 个人主体：最多 **25 个**小游戏，**不支持虚拟支付**（道具内购），**广告变现可以**
- 企业主体：最多 **50 个**小游戏，内购与广告都行

本项目是纯单机 + 激励视频（IAA），个人主体够用。如果以后想卖皮肤/内购，一开始就得用企业主体。

### Step 3 · 申请开发权限（这一步最容易卡住）

抖音小游戏目前是**申请开发制**：部分账号登录后看不到「创建小游戏」，只有「申请创建」，
需要填一条**可体验的测试链接**，平台 1—2 个工作日答复。

> 链接填不出可体验的东西 → 直接驳回。
> **这正是本工程带网页演示版的原因之一**：把这个仓库的 GitHub Pages 地址填进去就行（见第四节）。

审批通过后账号才有创建权限。这一步和实名认证是两件事，别以为认证完就能建。

### Step 4 · 创建小游戏

控制台 → 创建小游戏 → 填：

- **名称**：4—30 字符，全平台唯一，支持中文数字英文，不能用特殊符号/生僻字/单个名词
- **预计开发引擎**：选「其他 / 原生 JS」这一类（本工程是原生 Canvas，不用 Unity/Cocos）
- **基本信息**：如实填，均为必填

创建完成后在应用详情页就能看到 **AppID**，复制下来。

> 名称要想清楚：上架后每个自然年只能改 2 次，且要和软著等资质文件名称一致，
> 否则备案、广告投放会卡。

### Step 5 · 备案

小游戏需要 **ICP 备案**（平台内有入口，按引导提交）。**没备案不能上线**，
这一步耗时最长，建议拿到 AppID 就并行去做，不要等代码写完。

### Step 6 · 装工具、导入项目

1. 下载**抖音开发者工具**（Windows / Mac，正式版）
2. 导入项目 → 选择本目录 `train-mystery-douyin-v3`
3. AppID 填进去（或先改 `project.config.json` 的 `appid` 字段）
4. 编译

导入后默认跑的是模拟器。模拟器能验界面和逻辑，但**音频、震动、分享、广告、
切后台落盘这些必须真机**——点「预览」扫码用抖音 App 打开。

## 三、广告位 ID（adUnitId）是什么

激励视频广告位的编号，一串纯数字。代码里这样用：

```js
tt.createRewardedVideoAd({ adUnitId: "你的广告位ID" })
```

它和 AppID 是两个东西：AppID 认「哪个游戏」，adUnitId 认「哪个广告位」。

### 怎么拿

```
小游戏后台 → 商业化 → 流量主（申请开通，填结算银行卡 / 开票信息）
          → 流量主 → 广告管理 → 新建广告位 → 类型选「激励视频」
          → 得到 adUnitId
```

### 两个必须知道的限制

1. **开通流量主是前置条件**。不是上架就自动有，要单独申请。官方文档写明：
   小游戏版本审核上线后即可申请开通流量主，结算需要银行卡，企业主体需要开票信息。
2. **激励视频只支持单实例**。官方文档明确「申请多个激励视频广告位是无效的」，
   所以只需要一个 adUnitId，不要按场景建多个。

关于准入条件有个口径差异，需要你自己在后台确认：

- 官方「流量主接入指南」（小程序侧）明文写：**个人开发者需前一日 DAU > 50** 才能创建激励视频广告位
- 小游戏侧的实践口径是：**版本审核上线后即可申请开通**

两处说法不一致，**以你后台实际能不能点「新建广告位」为准**。
如果被 DAU 卡住，路径是先上线（不带广告）跑出基础量，再回来开广告位。

### 拿到后改哪里

`js/game/config.js`：

```js
rewardedVideoAdUnitId: "REPLACE_WITH_YOUR_AD_UNIT_ID",   // ← 换成真实 adUnitId
```

没配的时候会怎样？`js/platform/ad.js` 的 `isConfigured()` 返回 false，
按钮显示「广告不可用」，**明确不发奖**。这是刻意的风控——
先发奖再看广告的写法会被判刷量，直接封广告权限。

## 四、为什么还有网页版

三条用途，都不是「多做一个端」：

### 1. 申请开发权限时要有能体验的链接

见第二节 Step 3。平台要的是「点开就能玩」的 URL，
GitHub Pages 上的演示版正好是这个东西（已配好自动部署，见 `.github/workflows/pages.yml`）。

### 2. 没 AppID 时也能看效果

改一行代码想立刻看结果，走「浏览器刷新」比「工具编译 + 扫码 + 真机打开」快一个数量级。
而且 `preview.html` 支持直接跳到任意界面：

```
?modal=codex&tab=enemies     图鉴
?modal=battle&affix=frenzy   带词缀的战斗
?scene=route&advance=3       推进 3 个节点
?w=360&h=640                 小屏适配
```

截图走查也靠它——`_shots/` 里的图都是这么出的。

### 3. 它是同一套代码，不是另一套

`preview.html` 注入一个假 `tt` 对象，`js/platform/` 探测到没有 `tt` 就走浏览器分支，
**玩法逻辑、渲染、存档夹取全部是同一份文件**。不存在「网页版能玩、抖音版有 bug」这种分叉。

### 它不能替代真机

| 能力 | 网页版 | 抖音真机 |
|---|---|---|
| 界面与玩法逻辑 | ✅ | ✅ |
| 存档（localStorage / tt storage） | ✅ | ✅ |
| 音频播放 | 部分（浏览器自动播放策略会拦） | ✅ |
| 震动、分享、广告 | ❌ 全部降级为空操作 | ✅ |
| 切后台落盘、`tt.onError` | ❌ | ✅ |
| 真实性能（帧率、内存） | ❌ 采样不准 | ✅ |
| 真机字体/安全区差异 | 近似 | ✅ |

所以流程是：**网页版做日常开发与走查 → 真机做验收 → 提审**。

## 五、没有 AppID 现在能验证什么

不需要任何平台账号，当前就能跑：

```bash
node tools/test-headless.js      # 52 项，走 Node 分支，覆盖完整玩法链路
node tools/sim-balance.js 300    # 300 局平衡模拟
node tools/build-bundle.js       # 打浏览器包
start tools/preview.html         # 浏览器里真玩
```

**不能验证的**：`tt.*` 的真实行为（音频、震动、分享、广告、前后台切换）。
这些代码都已经写好并做了降级，但「降级路径对不对」只能真机验。

## 六、整条路径与卡点

| 步骤 | 耗时 | 卡点 |
|---|---|---|
| 注册 + 实名 | 几分钟 + 1 工作日审核 | 主体类型选错改不了 |
| 申请开发权限 | 1—2 工作日 | **要能体验的测试链接，否则驳回** |
| 创建小游戏拿 AppID | 几分钟 | 名称唯一，且后续改名受限 |
| ICP 备案 | **数天到数周** | 最长的一环，尽早并行做 |
| 软著（建议有） | 1—3 个月（加急另算） | 备案与广告投放常要求名称一致 |
| 开流量主 + 建广告位 | 上线后，几分钟 | 个人主体可能卡 DAU 条件 |
| 提审 | 1—3 工作日 | 材料不齐会来回 |

**最短路径**：注册认证 → 拿网页演示链接申请开发权限 → 创建应用拿 AppID → 备案并行启动
→ 真机验收 → 提审 → 上线后开流量主拿 adUnitId → 填回配置再提一版。

备案没下来之前，代码侧一切都能做完——这也是为什么工程里所有平台能力都做了降级：
**没有 AppID 不是阻塞项，备案才是唯一的长周期依赖。**

## 分享图的路径形态（提审前真机确认一次）

`tt.shareAppMessage({ imageUrl })` 现在传的是**包内相对路径**（`assets/share/*.png`）。
浏览器与 Node 环境下这条路径没有任何问题，但真机上是否接受包内路径、
还是必须走 `tt.getFileSystemManager().readFile` 转 base64 / 上传后拿 https 链接，
需要在真机确认一次。

三种做法的影响面：

| 形态 | 改动 | 备注 |
|---|---|---|
| 包内相对路径（现状） | 无 | 最省事，若支持就保持 |
| 本地绝对路径 | `platform.share` 里把相对路径拼成 `tt.env.USER_DATA_PATH` 下的文件 | 需要先把资源拷出去 |
| 网络 https | 上传到 CDN，`config` 里配域名 | 需要域名与备案 |

结论：**先按现状提审，真机验证失败再按表格换第二或第三种**。
换的时候只动 `platform.share`，`text.share` 里的三张路径不动。
